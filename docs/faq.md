# FAQ

## Сервер хранит закрытые ключи?

Нет. Ключ остаётся в браузере и используется плагином КриптоПро. Сервер видит
только сертификат и готовую CMS.

## Подходит ли пакет для квалифицированной подписи?

Да, для ГОСТ Р 34.10-2012 / CAdES-BES. Юридическую силу определяет сертификат,
аккредитация УЦ и политика организации, а не пакет. См.
[правовые аспекты](legal.md).

## Можно ли подписать документ несколькими подписями?

Да. Подписи добавляются последовательно: подписанный PDF можно снова передать
в `prepare_signing`. Для проверки нужной подписи используйте `signature_index`.

## Нужен ли КриптоПро на сервере?

Нет. CSP нужен только в браузере плагину. Docker-образ с CSP в репозитории
используется исключительно для интероп-тестов.

## Где хранить подписанные PDF?

В приватном хранилище: локальном каталоге без публичного URL или в S3 с
приватным бакетом и подписанными ссылками. См.
[эксплуатацию](operations.md).

## Как проверять отзыв без интернета?

Загрузите CRL и ответы OCSP заранее и передайте их в
`DJANGO_PDF_SIGN["VERIFY"]["CRLS"]` и `["OCSPS"]`. Сетевая загрузка по умолчанию
выключена.

## Почему проверка цепочки по умолчанию выключена?

Чтобы не делать сетевых запросов и не выбирать доверенные корни за приложение.
Включайте `CHECK_CHAIN` и задавайте `TRUST_ROOTS` осознанно.

## Поддерживается ли Django 4.2?

Нет. Минимальная версия — Django 5.2 LTS; 6.0 и 6.1 также поддерживаются.

## Это официальная подпись по 63-ФЗ?

Пакет формирует и проверяет CAdES-BES/PAdES. Юридическая значимость зависит от
сертификата, УЦ и инфраструктуры организации; пакет сам по себе не делает
подпись квалифицированной.
